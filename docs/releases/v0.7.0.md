# THEIA v0.7.0

> 状态：源码和测试已经完成验收；发布文件与 GitHub Release 状态由正式发布流程补充。
> 当前桌面版本元数据为 `0.7.0`。

## 1. 版本定位

`v0.7.0` 是相对于 `v0.6.3` 的功能性更新。它把北化在线 THEOL 的课程资料、作业和在线测试从“来源链接和摘要”推进为“可追踪、可校验、可落盘的本地资料链路”，同时提供给外部本机 Agent 使用的确定性同步入口。

本版本的核心结果不是增加一个新的对话能力，而是让同步任务直接经过 THEIA 的本地同步器：

```text
THEOL 页面/API
  -> SessionClient / THEOL adapter
  -> 解析、身份校验、截止时间过滤
  -> 本地 UTF-8 页面和文档附件归档
  -> CampusStore / sync provenance
  -> THEIA 课程、作业界面和 loopback API
```

课程资料和作业抓取不经过模型，也不通过 `/v1/agent/chat` 转发。

## 2. 用户可见更新

### 2.1 课程资料

课程界面的资料范围收敛为三类：

- 课程介绍；
- 教学大纲；
- 教学日历。

课程资源树、视频入口和其他无关栏目不再混入“课程资料”主视图。课程基本信息仍保留课程名称、教师、院系、选课人数、资源数和作业数等可读摘要。

资料抓取在“课程”界面单独执行。课程资料刷新按钮只刷新资料域，不会因为打开课程窗口而重新执行完整校园同步；普通同步也不会被资料详情页拖慢。

每份资料现在可以包含：

- 原始来源 URL；
- 归一化后的本地 HTML 页面；
- 本地文档附件；
- UEditor 或 iframe 正文的本地副本；
- 本地保存状态、字节数、SHA-256 和抓取时间；
- 资料抓取失败或部分失败的安全错误摘要。

THEOL 旧页面经常声明 GBK，但实际返回内容可能已经是 UTF-8。本版本在来源读取和本地归档边界处理字符集，并把归档 HTML 统一写成 UTF-8，避免课程介绍、大纲和日历打开后出现乱码。启动时还会修复旧归档中“UTF-8 字节 + 旧 GBK 声明”的文件。

### 2.2 作业和在线测试

作业与测试放在“作业”界面，由单独的同步动作负责。同步内容包括：

- 普通作业；
- 混合式作业页面；
- 在线测试；
- 测试结果/查看结果入口；
- 截止时间、提交状态和成绩（来源提供时）；
- 任务详情正文；
- 题目、选项和文本题控件（在线测试）；
- 任务页面中出现的文档附件。

默认只保留当前截止时间尚未到达的作业和测试。无法解析截止时间的记录不会被假装成已过期；它们保留为待进一步核对的当前任务，避免因旧页面格式变化误删用户任务。

任务详情归档采用独立目录和稳定任务 ID。文档类附件会保存到本地并写入附件元数据；图片、视频和音频不会被下载。支持的主要文档类型包括 PDF、DOC/DOCX、PPT/PPTX、XLS/XLSX、TXT、MD、CSV、RTF、ODT、ODS 和 ODP。没有明显扩展名但响应的 `Content-Type` 或 `Content-Disposition` 明确为文档的下载，也会按文档保存。

### 2.3 刷新行为

- 普通校园同步不主动执行课程资料详情抓取。
- 课程资料在课程界面通过独立按钮刷新。
- 作业与测试通过作业界面的独立刷新动作执行。
- 作业扫描按课程顺序访问 THEOL，并使用 THEOL 独占队列，避免多个来源窗口互相抢占会话。
- 资料和任务的详情归档使用本地原子写入；同一文件刷新失败不会留下半个新文件。

### 2.4 本机同步 API

桌面客户端提供明确的：

```http
POST /v1/sync
Content-Type: application/json
Authorization: Bearer <本次运行的本机令牌>

{"domains":["theol-course-details","assignments"]}
```

该入口：

- 只接受明确的数据域；
- 直接进入 THEIA 主进程同步编排器；
- 不创建 Agent 线程；
- 不调用模型；
- 不控制桌面窗口；
- 不执行学校侧提交、选课或其他不可逆写入。

当前与 THEOL 相关的域包括 `theol-courses`、`theol-course-details`、`theol-notices` 和 `assignments`。外部 Agent 应先调用明确同步，再读取 `/v1/courses`、`/v1/assignments`、`/v1/workspaces` 或完整快照；不能把抓取请求发给 `/v1/agent/chat`。

本机 API 仍只监听 `127.0.0.1`。它不是手机接口、局域网接口或公网接口。

## 3. 作业抓取流程

### 3.1 发现阶段

1. 从当前已认证的 THEOL 课程快照取课程名单。
2. 对每门课程进入课程上下文。
3. 读取课程页中的作业入口和在线测试入口。
4. 如果页面没有明确入口，使用有界的历史兼容入口。
5. 读取作业列表页和在线测试列表页。
6. 只接受唯一任务详情 URL：
   - 普通作业使用唯一 `hwtid`；
   - 在线测试使用唯一 `testId`。

列表控制页、分页链接、统计页和没有唯一任务 ID 的 URL 不会被当作任务记录。

### 3.2 校验阶段

进入详情页之前和之后都校验：

- 最终 URL 的任务类型和任务 ID；
- 页面中的课程 ID、`lid`、`cateId` 或等价 DOM 证据；
- 课程入口和任务入口属于同一个 THEOL 课程上下文。

课程页、任务列表页或详情页被重定向到其他课程/任务时，该记录失败并留下诊断，不会被写入目标课程。

移动端待办接口是全局 feed，只能在当前认证课程名单中匹配 `courseId` 后导入。未知课程即使返回了合法任务也会被丢弃，防止跨课程污染。

### 3.3 过滤和持久化阶段

- 截止时间已到的记录不进入当前 `assignments` 集合；
- 作业详情 HTML 归一化为 UTF-8 后保存；
- 文档附件按白名单下载并校验响应类型；
- 页面中的本地附件链接改写为归档内相对链接；
- UEditor iframe 的占位内容 `内容读取中...` 会尝试从父页面的 `_content` 字段恢复；
- 在线测试题目保留题号、题型、题干和选项；
- 任一附件失败会将任务标记为部分成功，而不是伪装成完整成功。

## 4. 本地存储

桌面数据根默认位于 `%APPDATA%\THEIA`。THEOL 资料归档布局为：

```text
THEIA/
  theol/
    course-materials/
      <course-id>/
        课程介绍-<stable-id>.html
        教学大纲-<stable-id>.html
        教学日历-<stable-id>.html
        <文档附件>-<hash>.<ext>
    assignments/
      <assignment-id>/
        <任务标题>-<stable-id>.html
        <文档附件>-<hash>.<ext>
```

这里的 `<stable-id>` 和 `<hash>` 由本地服务生成，不能由 renderer 或远端文件名直接控制。所有文件都通过临时文件加原子重命名落盘。

作业工作区仍是另一层：

```text
THEIA/
  course-work/
    <assignment-id>/
      manifest.json
      task.md
      answers.template.json
      attachments/
```

`theol/assignments` 是来源资料归档；`course-work` 是用户点击“准备工作区”后生成的工作包。二者不能混为一谈。

## 5. 失败和空结果语义

本版本不再把“请求成功但解析为空”直接解释为“学校没有作业”。每个同步域同时记录：

- 是否尝试过；
- 是否成功；
- `complete`、`partial` 或 `unknown`；
- 是否确认为空；
- 是否保留旧数据；
- 最近成功时间和最近尝试时间；
- 课程成功数、失败数和移动端 fallback 状态；
- 可安全展示的错误码。

只有完整且明确确认为空的作业扫描，才可以清理旧的当前任务。课程页失败、移动端接口失败、身份校验失败、附件失败或部分课程失败时，旧的有效任务继续保留，并将最新失败标记为 stale/partial 语义。

## 6. 安全边界

- 密码、Cookie、认证页面、session token 和模型 API Key 不进入 `CampusState`、Feed、本机 API、日志或发布归档。
- THEOL 抓取是只读读取；不代替用户提交作业或在线测试。
- 在线测试答案只能在用户明确使用现有操作时写入内置页面，最终提交仍由用户完成。
- 不下载视频、音频或图片作为课程资料或作业附件。
- 不把桌面 loopback API 暴露到局域网或互联网。
- 本版本不增加新的模型能力，也不允许模型成为课程资料抓取的隐式依赖。

## 7. 兼容性和升级注意

- 既有 `CampusState`、Feed 和集合 API 保持兼容；新增字段均为可选本地归档元数据。
- 旧的 THEOL HTML 归档可以在启动修复阶段被重新写成 UTF-8；修复失败时保留原文件并记录错误。
- 失败同步不会无条件清除旧课程、作业或资料。
- 当前桌面版本元数据为 `0.7.0`；`package.json`、锁文件、README 下载链接、发行说明和打包产物文件名必须保持一致。
- Android 是独立项目，不因为桌面版本命名为 `0.7.0` 就直接修改 Android 的包名、存储键或版本号。

## 9. 版本结论

版本号：**`0.7.0`**。

理由：本轮增加了用户可见的 THEOL 课程资料本地归档、作业/测试独立同步、文档附件下载和新的确定性本机同步 API，属于向后兼容的功能性增加；没有必要升到 `1.0.0`，因为桌面端真实线上覆盖、安装包发布和手机版合同对齐仍然需要独立收口。

本次正式发布流程：

1. 统一版本元数据为 `0.7.0`。
2. 重新运行完整测试、lint、TypeScript 检查和生产构建。
3. 生成 Windows 安装包和源码归档。
4. 运行 packaged smoke，核对安装包、源码归档和 SHA-256。
5. 以打包后的真实文件名和校验值补充本文件的发布文件段落。
6. 创建 `v0.7.0` tag 和 GitHub Release。
