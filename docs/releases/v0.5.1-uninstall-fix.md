# Windows 11 25H2 卸载文件写入错误修复

## 问题报告

- **版本**: THEIA 0.5.0
- **平台**: Windows 11 25H2
- **症状**: 卸载时提示"无法打开要写入的文件"

## 根本原因分析

### 问题定位

1. **异步写入竞争**: THEIA 的数据持久化使用了队列化的异步写入操作
2. **不完整的关闭等待**: `shutdownServices` 函数等待了部分异步操作，但遗漏了 store 的操作队列
3. **卸载时机冲突**: Windows 卸载程序在应用退出后立即尝试删除文件，但此时 store 的写入操作可能尚未完成

### 代码层面

```javascript
// core/store.mjs
export class CampusStore {
  constructor(root) {
    // ...
    this.operationQueue = Promise.resolve()  // 操作队列
  }

  enqueueOperation(operation) {
    const pending = this.operationQueue.catch(() => {}).then(operation)
    this.operationQueue = pending
    return pending
  }

  async update(mutator) {
    return this.enqueueOperation(async () => {
      // ... 执行写入操作
    })
  }
}
```

```javascript
// electron/main.mjs (修复前)
async function shutdownServices() {
  // ...
  await Promise.allSettled([
    advisorRuntime?.flush?.(),
    courseWorkQueue?.close({ cancelRunning: true }),
    feedWrite,           // ✓ 等待
    diagnosticWrite,     // ✓ 等待
    // store?.drain(),   // ✗ 缺失！
    localApi?.close(),
    viteServer?.close(),
  ])
}
```

### 文件锁定场景

1. 用户触发卸载
2. Windows 发送退出信号给 THEIA
3. `shutdownServices` 开始执行
4. Store 有一个待处理的 `update` 操作正在写入 `AppData\Roaming\THEIA\data\manifest.json`
5. `Promise.allSettled` 完成（但未等待 store）
6. 应用进程退出
7. **卸载程序尝试删除 THEIA 目录** → 文件仍被锁定 → 错误！

## 修复方案

### 1. 添加 `drain()` 方法

在 `CampusStore` 中添加等待操作队列完成的方法：

```javascript
// core/store.mjs
async drain() {
  await this.operationQueue.catch(() => {})
}
```

### 2. 在关闭时等待

在 `shutdownServices` 中调用 `drain()`：

```javascript
// electron/main.mjs
async function shutdownServices() {
  // ...
  await Promise.allSettled([
    advisorRuntime?.flush?.(),
    courseWorkQueue?.close({ cancelRunning: true }),
    feedWrite,
    diagnosticWrite,
    store?.drain(),      // ✓ 新增
    localApi?.close(),
    viteServer?.close(),
  ])
}
```

## 修复效果

- ✓ 所有待处理的数据写入操作在应用退出前完成
- ✓ 文件锁定在卸载程序运行前释放
- ✓ 卸载过程顺利完成，无文件访问错误

## 测试建议

1. **正常关闭测试**: 运行应用 → 触发数据写入 → 立即关闭 → 检查数据完整性
2. **卸载测试**: 安装 → 运行 → 触发数据写入 → 关闭 → 立即卸载
3. **压力测试**: 连续触发多个写入操作 → 关闭 → 验证所有操作都已完成

## 技术细节

### 操作队列机制

CampusStore 使用链式 Promise 队列确保写入操作的顺序性：

```
operation1 → operation2 → operation3 → ...
```

每个操作通过 `enqueueOperation` 添加到队列末尾，`drain()` 等待当前队列的尾部 Promise 完成。

### Promise.allSettled 的使用

`Promise.allSettled` 确保所有关闭操作都被尝试，即使某些操作失败：

- 不会因为单个操作失败而中断其他关闭步骤
- 所有操作完成后才继续退出流程

## 预防措施

对于未来的异步资源管理：

1. 所有长生命周期的异步服务应提供 `close()`、`flush()` 或 `drain()` 方法
2. `shutdownServices` 应等待所有此类方法完成
3. 添加关闭超时保护，避免无限期挂起
