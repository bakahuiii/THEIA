## 1. 结论

1. 当前本地分片存储健康：主 manifest、备份 manifest 均有 18 个分片，路径、schema、kind 和 SHA-256 引用全部匹配。
2. 培养计划已按 PDF-only 合同修复：`records = []`、`attachments = 1`，只保留当前专业的官方 PDF。
3. 培养计划 PDF 已与校历 PDF 放入同一目录 `academic-calendar/assets`，旧 `data/attachments/jwglxt` 中没有遗留 PDF。
4. 浏览器同步失败的根因是培养计划页面专业选择器默认为“全部”，首页 profile 没有专业 ID；适配器因此正确拒绝猜测并跳过 PDF。现在会从认证课表 JSON 的 `xsxx.ZYH_ID/ZYMC` 获取当前学生专业，再筛选并下载唯一 PDF。
5. API 和浏览器都经过同一归一化边界；浏览器 PDF 失败时不会生成其它专业计划或伪造记录，允许由另一通道按域 fallback。
