# THEIA 当前数据结构说明

实现快照 - 面向代码审查与后续数据层重构

**日期:** 2026-08-17

**规范状态:** 当前实现结构，不是未来方案或接口猜测

**主模型:** theia-campus-data/v1 的 CampusState

**隐私范围:** 省略账号、密码、Cookie、session、授权头、个人值、原始 HTML/JSON 与附件二进制

> **如何阅读**  本说明从保存的规范化模型开始，再说明采集结果、同步证据、分片存储和不同读取投影。null 表示当前无值或未获得该可选值；空数组不自动表示学校确认无数据，必须结合 sync.domains 解释。

## 1. 结构边界与总览

**主边界:** CampusState 是持久化的业务快照。它包含用户可以离线阅读的规范化校园数据、低敏感设置和同步证据；它不包含密码、独立 API cookie jar、Electron 浏览器 cookie/session storage、模型 API Key、邮件协议密码、原始认证页、附件二进制和可重放的学校写操作参数。

| **层** | **主要对象** | **职责** |
| --- | --- | --- |
| 采集与解析 | 适配器、SessionClient、AcademicApiClient、parser | 从 JWGLXT / THEOL / 本地目录读取，只产生受控、只读的结构化结果。 |
| 规范化状态 | CampusState | 统一字段、类型、时间和默认值；是持久化与本地计算的基准。 |
| 持久化 | theia-sharded-store/v1 manifest + SHA-256 fragments | 原子提交、备份恢复、动态学期片段。 |
| 有界读取 | renderer snapshot、UserData DTO、loopback API、MCP/AI projection | 针对不同消费者裁剪大字段、内部字段和高风险内容。 |

| **字段 / 主题** | **当前实现的结构与语义** |
| --- | --- |
| **根 schema** | CampusState.schema 固定为 theia-campus-data/v1；appVersion 来自应用版本；createdAt / updatedAt 是快照元数据。 |
| **主要集合** | profile、terms、courses、schedule、exams、grades、selectedCourses、academicProgress、academicExtras、assignments、workspaces、notices、emails、dataCatalog、sync、settings。 |
| **ID 原则** | 业务记录都有稳定字符串 id；扩展资料与附件可由稳定散列生成。内部网页 ID 可作为受控字段参与本地逻辑，但不会作为普通用户数据 DTO 的默认输出。 |
| **时间原则** | 收集/刷新时间通常为 ISO 8601 字符串；termId 是学年学期标识；页面显示时间与采集时间不是同一概念。 |
| **来源原则** | 核心实体以 source: jwglxt \| theol 标注平台，sourceUrl 是可选来源页。数据通道 accessMode 目前不是这些通用实体的逐条字段。 |

## 3. 核心学业实体

### 3.1 Profile 与学期

| **字段 / 主题** | **当前实现的结构与语义** |
| --- | --- |
| **Profile.name / studentId** | string \| null；姓名与学号。敏感个人值，外部导出必须由用户明确选择并按使用目的裁剪。 |
| **Profile.gpa** | number \| null；资料页可提供的 GPA，不等同于由成绩重新计算的值。 |

| **Profile.academicClass** | string \| null；行政班。 |
| **Term** | { id: string, year: number, term: string, label: string }；作为课程、课表、成绩、考试的常用关联键。 |

### 3.2 Course

| **字段 / 主题** | **当前实现的结构与语义** |
| --- | --- |
| **必填** | id、title、source。source 仅允许 jwglxt 或 theol。 |
| **识别与学期** | code、termId、termIds、classId；均为可选字符串，termIds 可描述跨学期关联。 |
| **展示与教学** | teacher、credits、category、location、description。credits 为 number \| null。 |

| **采集证据** | capturedAt；该实体当前没有 accessMode、rawPayload、cookie 或 requestHeaders 字段。 |

### 3.3 ScheduleItem

| **字段 / 主题** | **当前实现的结构与语义** |

| **时间** | examTime、startAt、endAt；可同时保留原始显示时间与结构化开始/结束时间。 |

| **导航** | sourceUrl。 |

### 3.5 Grade 与成绩尝试

| **字段 / 主题** | **当前实现的结构与语义** |

### 4.3 AcademicAnalysis（本地派生，不是学校原始返回）

| **字段 / 主题** | **当前实现的结构与语义** |
| --- | --- |
| **schema / evaluatedAt** | theia-academic-analysis/v1 与分析计算时间。 |
| **gpa** | value、officialValue、computedValue、source(official/computed/unknown)、credits、includedCourses。 |

## 6. JWGLXT 扩展资料 academicExtras

**容器语义:** academicExtras 以一个统一 envelope 保存低频、复杂或多路由的教务资料。核心字段不保存 raw HTML、raw JSON、请求参数、cookie 或隐式认证细节。每个域独立记录完整性与查询统计，因此不能只用 records.length 判断有没有数据。

| **字段 / 主题** | **当前实现的结构与语义** |
| --- | --- |
| **AcademicExtras** | schema、capturedAt、parserVersion、domains: Record<string, AcademicExtraDomain>。当前 parser 版本为 jwglxt-extra/v5。 |
| **AcademicExtraDomain** | label、routeCodes[]、sourceUrl、capturedAt、completeness、queryStats、messages[]、filters[]、attachments[]、records[]。 |
| **queryStats** | attempted、succeeded、failed、capped；表示白名单查询处理情况。 |
| **attachments** | id、label、type、sourceUrl、cached、bytes、sha256、filename。可用于本地附件打开，二进制不嵌入 CampusState。 |
| **AcademicExtraRecord** | id、title、fields[{name?,label,value}]，允许其它已净化键。fields 是最稳定的展示/导出形式。 |
| **recordCount** | 只在有界 renderer snapshot 中补充；规范化存储仍保留 records。它保证大 records 被裁剪后仍能显示数量。 |

### 6.1 当前扩展域清单

| **域 ID** | **中文标签** | **路由数** | **典型记录/附件** |
| --- | --- | --- | --- |
| academic-plan | 培养方案与教学执行计划 | 1 | 仅当前专业的官方培养计划 PDF 附件。 |
| graduation-audit | 毕业审核 | 1 | 审核结果/条件状态。 |
| grade-details | 成绩明细 | 1 | 逐条成绩明细；renderer snapshot 保留本域 records，供本地分组页面使用。 |
| exam-extra | 考试附加信息 | 3 | 补考、名单或设计页展示的考试相关资料。 |
| free-classroom | 空闲教室 | 1 | 教室、时间、筛选结果。 |

> **读写边界**  当前产品启用 5 个扩展业务域、7 个只读路由。学业预警和毕设与论文是显式忽略域，旧快照加载时会清除；按周课表、全校课表、档案与事务等重复页面同样不再抓取、索引或暴露。名称看似动作的页面只读取既有数据行；不读取或执行专业确认、提交、上传、删除等学校侧操作。

## 8. 同步 provenance 与结果语义

**为什么重要:** CampusState.sync 同时保存一次聚合同步的时间线、来源连接状态与每一个数据域的 outcome。它是解释“本地没有记录”时必须一起读取的证据层。

| **字段 / 主题** | **当前实现的结构与语义** |
| --- | --- |
| **sync 聚合字段** | lastStartedAt、lastCompletedAt、lastRunAt、lastSuccessAt、lastError、runId。lastSuccessAt 不能代替每个域的 sourceSucceededAt。 |
| **sync.sources** | Partial<Record<jwglxt \| theol, SourceStatus>>。每个 source 可有 connected、checkedAt、authRequired、error、url、errors[]。 |
| **sync.domains[domain]** | schema=theia-domain-provenance/v1、runId、source[]、attempted、succeeded、attemptedAt、completedAt、status、capturedAt、sourceSucceededAt、emptyConfirmed、contentEmptyConfirmed、retainedPrevious、completeness、parserVersion、errorCode、成功/失败 term ID。 |
| **outcomes** | 域下可存在每来源 outcome：schema=theia-domain-outcome/v1，字段与域级 provenance 对应。用于保留独立来源的事实。 |
| **status** | never、not-attempted、succeeded、failed、auth-required。 |
| **completeness** | complete、partial、unknown。必须与 status / emptyConfirmed 一起解释。 |
| **emptyConfirmed** | 最近一次成功且完整尝试明确无记录时为 true，可安全清空本域。 |
| **contentEmptyConfirmed** | 当前保存内容曾被完整来源确认为空；与本轮是否尝试不同。 |
| **retainedPrevious** | 本轮失败/不可靠空结果而保留旧数据时为 true。旧数据仍可读，但不能描述成刚从学校确认。 |

| **看到的现象** | **正确解释** | **存储动作** |
| --- | --- | --- |
| 域不存在或 never | 尚未采集 / 不可知 | 不创建“无数据”结论。 |
| complete + emptyConfirmed | 学校侧本次明确无记录 | 可替换为确认空。 |
| partial 或筛选条件不完整 | 不能推断无记录 | 不以空结果覆盖旧值。 |
| failed / auth-required | 本轮未获得可信新值 | 保留旧数据，retainedPrevious=true。 |
| 成功部分学期 | 范围内成功、整体不完整 | 只替换成功范围；successfulTermIds/failedTermIds 作证据。 |

## 10. 分片存储与恢复

**提交模型:** 持久化根使用 theia-sharded-store/v1。CampusStore 将一个规范化 CampusState 拆成内容寻址片段，manifest 指向对象并保存哈希；写入先产生新对象，再备份并原子替换 manifest。

| **分片键** | **内容** |
| --- | --- |
| state/meta | appVersion、createdAt、updatedAt。 |
| state/profile / state/settings / state/sync | 基础资料、非秘密设置、同步证据。 |
| academic/terms、courses、schedule、exams、grades、selected-courses、progress、extras | 核心 JWGLXT/学业数据。 |
| coursework/assignments、coursework/workspaces | 课程任务与工作区 metadata。 |
| communication/notices、communication/emails | 通知与邮件 metadata/经净化正文。 |
| catalog/index | fitness、academicCalendar 和 schoolSchedule 的索引；schoolSchedule records 从 index 剥离。 |
| catalog/school-schedule/<term> | 按学期动态创建的完整全校课表缓存记录。 |

| **字段 / 主题** | **当前实现的结构与语义** |
| --- | --- |
| **manifest** | data/manifest.json；备份为 manifest.json.bak。每片是 theia-state-fragment/v1，带内容 hash。 |
| **对象布局** | data/objects/<kind>/<sha256>.json；不可变对象可被当前或备用 manifest 引用。 |
| **加载恢复** | 主/备 manifest 均检查 schema、相对路径边界、fragment kind 和 digest；单片损坏可从另一份 manifest 恢复。 |
| **旧格式** | buct-data.json 与 .bak 保留为旧迁移来源；新写入以 sharded manifest 为主。 |
| **避免误删** | 新分片对旧 manifest 可为可选；动态 schoolSchedule 分片不会因一次普通同步未包含此域而删除。 |

## 12. 当前访问方式与数据统一的事实

**实装现状:** JWGLXT 的 direct API client 与 authenticated browser session 具有不同 cookie 容器和认证生命周期。前者能否读数据不等同于后者能否直接打开来源页面。SyncService 可以优先使用 API，再在失败域回退会话读取，但当前规范化核心记录以平台 source 区分，不保留一条记录的 accessMode 枚举、请求证据或双通道副本。

**结构结论:** 因此，当前“数据统一”主要指同一业务语义进入统一集合、使用统一 empty/partial/retainedPrevious 规则；它不等价于“可以从每条记录审计 API 与前端模拟各自得到的同一份数据”。若后续要求两种通道同时保留、可并列对比，应引入 acquisition envelope（platform、accessMode、evidence、capturedAt、canonical record reference）并把它与业务实体分离。

## 13. 隐私、保留与使用规则

| **字段 / 主题** | **当前实现的结构与语义** |
| --- | --- |
| **绝不进入 CampusState** | 密码、邮箱授权码、模型 API Key、Cookie、浏览器 session、独立 API cookie jar、原始认证页、绝对本机路径、附件二进制、可重放学校写操作字段。 |
| **仍然敏感** | 姓名、学号、成绩、GPA、选课、考试位置、邮件发件人/正文、培养计划、来源 URL、本地工作区 metadata。 |
| **外部导出** | AI/MCP 读取必须使用脱敏、有界投影；需要个人资料时由用户明确选择。AI 导出包不是 CampusState 的字节级备份。 |
| **旧数据保留** | 同步失败或不可靠空响应不应擦除已知旧值；数据陈旧要通过 provenance 显示，而不是伪造实时性。 |
| **删除** | 迁移或新格式写入不授权清理旧 snapshot、manifest、工作区、校历资产或 course-selection journal；删除需要单独的用户面对策略。 |

## 14. 审查时优先看什么

**数据可信度:** 先看 sync.domains.<domain> 的 status、completeness、emptyConfirmed、contentEmptyConfirmed、retainedPrevious、capturedAt / sourceSucceededAt，再解释 records 或业务字段。

**性能边界:** 普通渲染页面应优先使用 overview、domain summary 和 records；只有确实需要完整关系计算或本地导出时才读取完整 snapshot。

**平台边界:** 教务的 API 与浏览器会话、THEOL、体测、校历、全校课表不应被误视为一个单一来源。它们分别有自己的采集边界、缓存边界、完整性和权限语义。
