# THEIA 当前工作日志

数据层收尾审查版 - 仅记录当前实现与本轮本地核验

**日期:** 2026-08-18

**范围:** 北京化工大学教务（JWGLXT）、THEOL、相关本地缓存与只读读取面

**状态:** 文档收尾；未制作发布包、未提交学校侧操作

**审查边界:** 不包含账号、密码、Cookie、会话值、授权头、个人样本或原始页面

> **本轮结论**  THEIA 已形成一个可持久化的规范化 CampusState、分片存储和多种只读读取面；教务快路径、低频扩展资料、THEOL 课程作业和本地数据目录被明确分开。普通渲染器不再长期持有大记录历史。

## 1. 本轮完成范围

**工作方式:** 本轮只复核当前源码、固定夹具、数据合同、归一化、存储、PDF 资产和读取面；不把历史学校端抓取结果当作当前数据证据。

**安全边界:** 本轮没有登录或读取学校端，没有把登录材料写入文档，没有读取或导出会话容器，也没有执行选课、申请、确认、提交、上传、删除、发信等学校侧操作。

| **字段 / 主题** | **当前实现的结构与语义** |
| --- | --- |
| **JWGLXT 快路径** | 资料、学期、课程、课表、成绩、考试、已选课程、学业进度、通知；由同步服务组织，认证方式可为独立教务 API 或已认证浏览器会话。 |
| **JWGLXT 扩展资料** | 当前产品启用 5 个业务域、7 个只读路由，统一保存到 academicExtras；学业预警和毕设直接忽略，档案与事务、按周课表、教务全校课表等重复域仅保留兼容清理逻辑。培养计划为 PDF-only：records 永远为空，最多保留当前专业 1 个 PDF；PDF 与校历中的其它 PDF 放在同一附件目录。 |
| **THEOL** | 课程、作业/在线测试、通知等课程平台数据；它是独立来源，不应以教务数据缺失或重复来评价。 |
| **本地目录** | 体测按学年缓存、全校课表按学期缓存、官方校历资产和结构化分析；三者不混入个人教务快路径。 |
| **读取面** | 完整快照、受限 renderer snapshot、用户数据 DTO、回环 HTTP API、Feed/CSV/ICS 和受控的 AI/MCP 读取面。 |

## 2. 平台与采集方式核对

| **平台** | **当前接入方式** | **结构化落点** | **边界** |
| --- | --- | --- | --- |
| JWGLXT | 独立 direct API client；已认证 browser/session client；扩展页受控页面/查询读取 | CampusState 的核心学业集合、academicExtras、schoolSchedule catalog | 只读白名单；不调用确认、提交、上传或其它动作端点。 |
| THEOL | 平台适配器读取课程、作业和通知 | courses、assignments、notices，及课程工作区元数据 | 与 JWGLXT 是不同平台，数据交集不代表可以相互覆盖。 |
| 体测平台 | 按学年读取并本地缓存 | dataCatalog.collections.fitness | 本轮不要求抓取体测内容；数据结构仍保留现有缓存合同。 |
| 教务处校历 | 官方资产下载、OCR/结构化分析缓存 | dataCatalog.collections.academicCalendar | 二进制资产与结构化日历分开；不把原始文件塞入状态 JSON。 |

> **访问方式说明**  当前常规 Course、Grade、Exam 等记录包含 source/sourceUrl 等来源信息，但没有逐条 accessMode 字段。direct API 和浏览器会话是适配器/会话层的不同通道，结果在规范化后进入同一业务集合；sync 记录来源和完整性，但不能从单条核心记录反推出其一定来自哪一种通道。

## 3. 扩展教务资料与培养方案

**刷新策略:** 扩展页不再被当作随启动全量爬取的对象。首次进入未采集域或用户明确请求时才按目标域读取；已有 capturedAt 的域优先展示本地快照。失败、认证失效、筛选不完整或空白占位页面不会覆盖旧记录。

| **资料类别** | **当前数据形态** | **特别处理** |
| --- | --- | --- |
| 培养方案与教学执行计划 | academicExtras.academic-plan 的 PDF-only 域与附件元数据；`records` 永远为空 | 官方 PDF 写入本地附件缓存；状态中仅存 id、filename、bytes、sha256、sourceUrl 等 metadata，最多保留当前专业 1 个文件。 |
| 成绩、考试、毕业审核 | 统一的 AcademicExtraDomain / AcademicExtraRecord | 页面表格或受控 JSON 被规整成字段列表；不保存 raw HTML、raw JSON 或请求参数。学业预警和毕设不进入新数据或旧快照归一化结果。 |
| 旧档案与事务页面 | 不再进入当前 `academicExtras` | 档案补充、按周课表、教务全校课表及申请/学籍/报名/评价壳页面已从 active 白名单移除；不会点击申请、确认、提交、上传、删除和操作按钮。 |
| 全校课表 | 已从 `academicExtras` 移除重复域 | 当前只保留 `dataCatalog.collections.schoolSchedule` 作为选课/检索使用的按学期缓存，避免与个人教务资料重复。 |

## 4. 数据层收束与读取优化

| **字段 / 主题** | **当前实现的结构与语义** |
| --- | --- |
| **规范化状态** | 空状态、输入迁移和每次加载均经 normalizeState；缺失字段补默认，富文本邮件按版本和安全规则净化。 |
| **分片存储** | CampusStore 将状态拆成稳定业务片段，以 SHA-256 内容寻址，manifest 与备份 manifest 原子替换；按学期全校课表独立片段。 |
| **同步 provenance** | 每个域保留 attempted/succeeded/status/capturedAt/emptyConfirmed/contentEmptyConfirmed/retainedPrevious/completeness/errorCode 等事实，避免把空数组当作已确认无数据。 |
| **用户数据 DTO** | 新增 overview、domain summary 和按页 records 读取；可检索、按学期、状态、类型过滤，页大小上限 100。 |
| **renderer snapshot** | 普通 renderer 获取到的 snapshot 会清除扩展域大历史（成绩明细除外）、全校课表 records 和邮箱 body/bodyHtml；保留 recordCount 供设置页和概览显示。 |
| **本机 HTTP API** | 仅绑定 127.0.0.1、只允许 GET/HEAD、严格 Host/CORS；提供完整快照与有界 DTO 两类读取路线。 |

## 6. 当前状态与后续审查点

**审查基线:** 当前文档描述的是共享工作树中已经存在的实现合同，不把模拟浏览器、直连 API、教务和 THEOL 的逻辑差异简化成一个“统一来源”。数据消费端应先看域级 provenance，再解释记录内容。

**通道证据边界:** Course、Grade、Exam 等核心记录不逐条保存 accessMode；当前以 `source` / `sourceUrl`、域级 sync provenance 和诊断事件记录通道及回退结果。若未来需要审计同一条记录的逐条采集通道，再新增 acquisition evidence 模型，不把未实现字段写入当前合同。

**未做操作:** 本轮没有生成安装包、源码包或新版本发布物，也没有清理旧快照、会话目录、缓存和其它共享工作树改动。
